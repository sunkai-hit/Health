# Health V0.1 安全、隐私与数据治理方案（设计稿）

> 2026-11-17 · **产品/工程安全要求，不是合规认证结论**。项目仓库目前 Public。不能向该仓库提交真实患者信息、处方原件、病历、密钥或带有健康数据的日志。

## 1. 风险与合规边界

健康事件中含有症状、药品、就医和医生医嘱，属于高度敏感信息。中国《个人信息保护法》第 28 条将“医疗健康”列为敏感个人信息；第 29 条规定处理敏感个人信息应取得单独同意（适用法律另有规定时从其规定）；第 31 条涉及未满 14 周岁未成年人的监护人同意。

**重要区分：** 中国法律没有简单规定所有健康数据一律绝对不能出境；是否应采用境内托管、何时涉及出境合规程序，需要根据用户主体、处理规模、个人信息处理者性质、跨境路径和适用规定进行具体评估。当前工程**不能默认**海外云存储或将全部健康数据发送第三方模型可行。

## 2. 隐私基线

| 数据类型 | 处理方式 | 第一阶段限制 |
|---|---|---|
| 账号标识 | 最小必要、单独认证、与档案隔离 | 禁止用户隐私字段进日志 |
| 症状及人体位置 | 私有敏感记录，按用户/档案授权 | 不放 URL 参数、不对第三方埋点开放 |
| 药物和实际服用 | 原始事实保留及用户更正版本 | 不自动推断药物剂量或是否遵医嘱 |
| 医生医嘱/处方 | 原文、来源、转录状态、变更历史 | 不将转录冒充经医生签署 |
| 原始附件 | 独立私有对象存储、短期访问令牌、扫描 | 原型仅本地预览 |
| OCR 草稿 | 明确“待用户确认”，候选字段不覆盖原文 | 尚未实现 |
| AI 分析 | 按用途的单独同意，最小字段，模型版本 | 真实分诊默认关闭 |
| 报告 | 选择内容、确认、可撤销分享、保留快照 | 演示仅浏览器打印 |
| 审计日志 | 操作 ID、时间、结果、请求关联 ID | 不记录正文、医嘱、附件内容 |

## 3. 身份和授权

- V0.1 建议先本人使用；家庭多成员作为单独设计，不继承任何“自动可访问家人数据”的权限。
- 服务器端所有资源按当前认证的 \`user_id\` 重新查归属；\`profile_id/event_id/order_id/attachment_id\` 是引用值，不是授权凭据。
- 防 BOLA/IDOR：对每个读写/导出/分享操作做对象级授权；API 一律限制 \`limit\`、速率和页面大小。
- 身份令牌放 HttpOnly / Secure Cookie；跨站写请求做 CSRF 防护，CORS 默认只开自己的 UI 域名；Cookie 使用正确 SameSite 规则。
- 会话可撤销、可注销；高敏感导出与删除操作需重新确认身份。
- 从一条处方关联实际服药时，必须验证处方、药品项、事件都属于同一用户并且满足同事件约束；仅数据库 FK 不够。

## 4. 敏感数据加密和机密

- 全程 TLS。正式存储应采用受控密钥管理和静态加密；必要时对敏感内容进行应用层加密并记录密钥版本，密钥不得硬编码。
- 推荐将索引必要的非内容字段与症状/医嘱/药物的加密载荷分开；不要将明文药名、诊断、医生内容作为数据库可查询列。
- 应实现密钥权限分离、轮换策略、备份恢复测试及审计；加密选择与搜索/查询能力的取舍需在安全评审中确认。
- 生产 Secrets、AI API Key、对象存储凭据只能使用受控机密存储，禁止放入 Public Repo 或公开 CI 日志。
- 采用最小权限的数据库与对象存储访问凭据；应用/CI/开发人员权限分离。

## 5. 上传附件与 OCR（尚未实现）

1. 前端先获得明确上传告知和授权。
2. 服务端生成一次性上传意图，校验账号、事件、文件名/类型/大小、服务端随机对象键。
3. 仅允许指定类型，做 MIME sniffing、大小限制、文件安全检查和扫描，不直接信任扩展名。
4. 默认私有存储，不以公开 URL 分发；按资源归属校验下载。
5. OCR 由经过审批的处理器读取授权数据，记录模型/规则版本及范围；第三方保留、训练、删除策略需验证。
6. OCR 生成候选草稿，所有药名、规格、剂量、频次、疗程需要用户逐项核对；不能将 OCR 结果伪造成医生正式签署的处方。
7. 取消/撤回授权、删除账户后的原件、OCR 草稿、缓存、备份和模型服务处理痕迹需有可操作的清理策略。
8. 当前单文件原型仅用浏览器对象 URL 预览本地虚构图片，没有网络上传、服务端存储或识别。

## 6. AI 分析和临床风险

- 纯记录、问询、事实摘要与真正的医学风险分诊分开部署开关。
- 任何实际分诊等级、紧急危险信号规则和处置建议必须先有专业医学审查、适用范围与验证集，不能用模型自由生成的“低风险”结论替代审核。
- 独立规则高优先级执行；模型不允许降低紧急提示级别，也不允许写入“已经服药”“医嘱被撤销”等事实。
- 关键字段不确定时保留未知；模型错误/延迟不得阻止用户保存事件。
- AI 模型调用最小化输入并记录授权版本，不能直接发送全部病史/处方附件。
- 不将 AI 输入输出、诊断猜测或用户正文放入普通 APM、日志、运营看板。

## 7. 数据主体权利和生命周期

- 用户可查看已保存数据、导出原始记录及报告；数据更正需保留必要历史。
- 支持撤回外部 AI 数据处理授权，撤回只影响后续处理；已完成的第三方处理依照约定和法律规范清理。
- 删除应区分单个事件/附件删除、账号永久删除、备份/日志中残留的清理期限；期限需要法规和产品评审确定，不能随意承诺立即从所有备份抹除。
- 导出或分享需显示内容选择与目的地；报告下载使用带过期的短期授权，不使用可公开枚举链接。
- 数据保留时长不直接猜测固定天数，必须由目的、法律和用户选择共同确定。
- 未满 14 岁用户/家庭成员需要独立监护授权设计，目前不纳入个人 MVP 的默认开放范围。

## 8. 威胁建模（STRIDE 思路）

| 威胁 | 主要风险 | 必须具备的防护 |
|---|---|---|
| 身份冒用 | 查看他人的病历 | 会话安全、多因素/二次验证（按风险）、限速 |
| IDOR | 越权获取处方或报告 | 每对象用户归属检查、不可预测 ID |
| XSS/HTML 注入 | 盗用会话或展示恶意文档 | 默认安全渲染、CSP、输出转义 |
| CSRF | 未授权创建/删除记录 | CSRF Token、Cookie 属性、来源检查 |
| 恶意文件 | 上传脚本或漏洞利用文件 | MIME 校验、扫描、私有桶、预览隔离 |
| 机密泄露 | AI Key/密钥泄漏 | Secret 管理、轮换、最小权限 |
| Prompt Injection | 病历文本诱导 AI 执行指令 | 报告/OCR 文本视为不可信、模型无直接写权限 |
| 误判/漏报 | 用户延误就医 | 医学审核、规则优先、未知处理、发布开关 |
| 数据跨境 | 不合法传送敏感个人信息 | 地域/供应商/处理链路审查 |
| 备份泄漏 | 长期敏感数据暴露 | 受控备份加密、恢复和删除机制 |

## 9. 安全验收门槛

- [ ] 已明确目标用户地区、处理目的、数据驻留与第三方 AI/OCR 处理方。
- [ ] 完成医疗健康敏感个人信息告知与适用的单独同意。
- [ ] 用户 A/B 越权读写、报告下载、附件访问全部拒绝。
- [ ] 所有机密不入 Git/前端构建/CI 日志；生产密钥可轮换。
- [ ] 数据库和对象存储具备可验证的保护、备份恢复及删除程序。
- [ ] OCR 草稿不创建“医生已核验”的医嘱。
- [ ] AI 失败时记录和报告功能正常；真实临床分诊未审核则关闭。
- [ ] 上传恶意文件、路径遍历、XSS/CSRF、速率限制测试通过。
- [ ] 报告用户确认、导出权限和过期分享机制通过测试。
- [ ] 有记录的数据泄漏响应和应急处置流程。

**重要：** 以上均为待实现/待验证要求，不能因为已写文档或已有原型而宣称产品符合医疗或隐私法规。
