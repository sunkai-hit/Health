### 新增 S2 安全负面用例（重点）

| 检查 | 已实际验证的结果 |
|---|---|
| 无 Bearer 令牌 | 访问事件资源返回 401 |
| 不支持虚构身份 | 拒绝领取演示令牌（422） |
| 有效签名 | A/B 可以在本机创建独立的短期令牌 |
| 篡改签名 | 401 |
| 过期令牌 | 401 |
| 错误 audience | 401 |
| 客户端指定归属 | 422 |
| 用户 B 列举 A 的事件 | 事件不在列表中 |
| 用户 B 持 A 的事件 ID 读取详情/症状 | 均返回 404 |
| 用户 A 列举 B 的事件 | 事件不在列表中 |
| 用户 B 往 A 的事件写症状 | 404，不能写入 |
| 用户 A 往 B 的事件写症状 | 404，不能写入 |
| 原 S1 场景 | 事件创建、症状密文读写和参数校验保持通过 |

## 二、问题收敛

| 问题 | 影响 | 最小修复 | 回归结论 |
|---|---|---|---|
| S2-B01 WebCrypto HMAC \`sig.buffer\` TS 类型不兼容 | 编译阻断，API 作业无法启动 | 将签名拷贝到明确的 \`ArrayBuffer\`，不修改验签规则 | CI 的 TypeScript 和 27 项 API 测试全部通过 |
| S2-N01 仍可在本地领取任意虚构用户令牌 | 演示身份不是正式身份认证 | 明确本地/虚构测试限制，不包装为生产账号 | 留待正式身份选型，不属于 S2 的漏洞修复 |
| S2-N02 不支持生产会话吊销、多设备及 Refresh Token | 正式发布阻断 | 保持公开部署关闭 | 下阶段账号认证安全底座 |
| S2-N03 没有真实 KMS、密钥轮换、数据删除和同意流程 | 正式发布阻断 | 保持只用合成资料 | 安全阶段门，不能真实上线 |
| S2-N04 处方、治疗、OCR、AI 和报告接口 | 产品后续范围 | 不引入 S2 | 已有需求按原优先级排队 |

## 三、完成定义与未完成边界

S2 完成条件：签名身份检查、事件读取/写入归属控制、两个虚构身份双向越权拒绝与原 S1 回归都通过。**不追加任何产品新模块。**

正式用户接入仍然需要另行确定和实现：
- 真实身份提供方与会话安全，包括用户身份核实、令牌管理及吊销；
- 根据目标用户地区选择部署与数据处理方案；
- 敏感信息处理告知、授权、同意撤回、导出和删除；
- 生产加密与密钥管理、备份恢复；
- 面向真实用户的安全与医学专业测试。

本轮只有本地模拟账号权限逻辑，**不能向用户提供真实健康数据服务**。代码先保持 Draft PR 待评审，不自动合并或公开部署。
