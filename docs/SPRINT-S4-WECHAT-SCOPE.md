# Sprint S4｜微信小程序首发形态基线（锁定）

日期：2026-11-17
分支：\`feature/mvp-s4-wechat-foundation\`
基于 S3 \`feature/mvp-s3-auth-boundary\`
目标：只搭建**原生微信小程序只读合成数据骨架 + 后端微信身份交换接口与测试**。

## 这轮只做

- [ ] 明确小程序注册与备案、境内托管、医疗健康敏感信息的数据处理阶段门。
- [ ] 微信原生小程序目录、页面配置、首页与演示事件时间线，**只读合成数据，不收集用户输入**。
- [ ] 后端 \`wx.login\` 临时 code → 微信 code2Session 的**独立服务端适配函数**，支持假网络单元测试；不挂真实 API 路由。
- [ ] 校验微信错误响应、不合法 OpenID、可选 UnionID 和 AppID/Secret 不可下发的边界。
- [ ] 使用 Node 测试校验小程序目录/静态数据与禁用健康真实数据写入；将这些测试纳入 CI。
- [ ] S3 的默认 Worker 全路径 503 保持不变，S2 虚构 A/B 账户仅在显式本地配置可用。
- [ ] 真实自动化检查通过后形成验收结论，保留 Draft PR。

## 明确不做

- **不接入正式 AppID/AppSecret**，不执行真实微信登录，不对外开放任何正式登录/注册接口。
- **不创建生产数据库**，不记录真实症状、病历、药品、身份、手机号或联系方式。
- 不开发完整人体图交互、实际健康数据录入、医嘱/处方、AI/OCR、家庭成员、推送、支付或报告。
- 不选择具体云商/域名，不伪称完成微信平台备案或医学业务资质。
- 不把 S3 的 OIDC BFF 改造成小程序直接持有第三方 OIDC Token；保留仅作未来其他客户端方案。

## 阻断问题与处理

- S4-B：演示页面发生真实联网或本地持久化、默认 Worker 开放了业务路径、微信 AppSecret/session_key 泄漏给客户端、静态构建/测试不通过。
- S4-N：小程序主体/AppID、备案、正式业务会话、生产 KMS/用户授权、境内云采购，后续独立阶段解决。
- S4-X：任何扩展产品模块，继续排队，不进入本轮。

处理顺序固定：“问题重现 → 最小修改 → 回归测试 → 记录结论”，不扩大已经冻结的需求范围。
