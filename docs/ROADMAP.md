# Health 需求到上线阶段路线图（建议）

> 仅定义阶段、交付物和进入下一阶段的条件；**不承诺固定日期或工期**，工期将在需求及技术方案确认后估算。

## 阶段 0：需求基线（当前）

**产出**：PRD V0.1、功能清单、概念数据模型、AI 安全边界、开放决策清单。  
**阶段门**：用户确认核心目标、P0/P1 范围、首批用户/部署地区；AI 医学安全边界不能存在理解歧义。

## 阶段 1：交互与 UX 设计

**建议优先输出页面**：
1. 首页（最近事件与快速记录）
2. 人体图症状录入（2D 正反面、一级/二级区域）
3. 健康事件详情与时间线
4. 用药记录
5. AI 问询/风险提示
6. 就医报告预览
7. 档案与隐私设置

**产出**：可交互原型、人体 SVG 标注方案、主要用户操作路径、状态空白/失败/无网络分支。  
**阶段门**：完成重点流程的可用性评审，医学顾问审核风险相关交互文案。

## 阶段 2：技术方案与安全设计

**产出**：模块边界、服务端 API、数据表及版本策略、加密与备份策略、用户授权流程、第三方 AI 数据传输说明、报告生成方案、日志脱敏方案、区域部署合规评估。  
**阶段门**：敏感数据处理审查和授权架构通过；形成研发任务拆分与估算。

## 阶段 3：可用 MVP

**推荐实施先后**：
- 基础身份与数据隔离
- 健康事件与时间线
- 人体图选择 + 症状记录
- 用药/就医/检查记录
- 事件汇总及 PDF 报告
- AI 问询与事实性整理（严格授权）

**阶段门**：端到端演示使用虚构数据完成“记录 → 补记 → 用药 → 事件报告”；安全与权限测试通过。

## 阶段 4：临床风险功能验证

**产出**：医学审核的规则集、问询用例、可追溯预警文案、合成/授权测试集、误报漏报评估、回归测试记录、法规分类评估。  
**阶段门**：满足预先约定的医学安全与监管条件后，才能对真实用户开启自动风险分级；否则作为关闭状态保留。

## 阶段 5：小范围使用与迭代

**观测**：记录耗时/完成率、事件持续补记率、报告核对修订率、医生反馈、隐私授权撤回、异常警示体验。  
**迭代**：语音、药盒 OCR、检查报告 OCR、历史趋势、家庭档案。

## GitHub 管理建议

- `main`：已评审的基准需求与代码。
- `docs/*`、`feature/*`：主题分支，采用 PR 评审。
- Issues：按主题追踪 Epics、功能、缺陷、设计决策与安全依赖。
- 标签：`product`、`ux`、`ai-safety`、`privacy`、`backend`、`p0`、`p1`（实际创建标签前需检查 GitHub 配置）。
- 文档维护：每次需求变更同时修改 PRD、功能清单、数据模型及验收口径。
