## 三、本轮实现与明确排除

**实现**：
- 微信小程序原生工程（可供开发者工具导入），带游客 AppID 占位；只读模拟资料。
- 微信后端临时登录凭证校验与 code2Session 请求适配，接口通过模拟 HTTP 测试。
- 小程序静态不含真实登录、不含客户端 AppSecret、无网络/本地持久化和健康资料输入的测试门槛。
- 产品架构 ADR、研发锁定范围、README 与路线图更新。

**排除**：
- 未在**微信开发者工具**中执行真实编译预览、设备调试或审核/发布。
- 未创建或绑定正式小程序 AppID、AppSecret、微信平台备案、后台 API 域名。
- 未真实调用微信服务器 code2Session（无真实凭据，全部是模拟网络响应）；没有真实微信登录路由。
- 没有真实 Health 身份、会话、账户恢复/吊销、用户授权和数据保护机制。
- 没有生产数据库、健康信息录入/存储/报告、处方/用药或 AI/OCR。

## 四、问题和需求收敛记录

| 问题/需求 | 分类 | 收敛结论 |
|---|---|---|
| 旧版 PWA 不符合微信首发形式 | 本轮架构更改 | 明确原生 WXML/WXSS；旧原型仅留 UX 参考 |
| S3 OIDC 是首发登录前置假设 | 本轮架构更改 | 取消首发前置；微信 code2Session 优先，OIDC 留备用 |
| 演示身份有误用风险 | 安全阶段门 | S3 fail-closed 默认 Worker 继续成功回归 |
| 中国大陆云/小程序登记及类目未定 | S5 前置 | 不临时选定云商/类目/主体；避免虚假上线声明 |
| 真实健康数据敏感信息单独同意 | S6 发布前置 | 保持写入关闭，不提前开放收集 |
| 处方、AI/OCR、家庭档案 | 业务后续 | S4 不做，保留原 PRD |
| 微信工具/真机实际可用性 | S5 研发与人工验收 | 当前静态结构通过不等于真机验收 |

**S4 无未关闭的自动化测试阻断；但真实上线阶段门全部保留。**

## 五、下一阶段仅推进的前置任务

1. 确认**小程序主体及正式 AppID**；校验类目和相应资质要求。
2. 选择适用于中国大陆的后端基础设施及 **HTTPS、合法域名/备案**方案，并评审健康数据存储/日志/备份流转。
3. 定义 Health 服务端真实会话、独立医疗健康敏感信息同意、数据导出删除、密钥/KMS 与安全测试方案。

这些要素未落实前不调用真实微信认证，也不允许真实用户输入任何健康数据。
