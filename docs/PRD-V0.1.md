# Health 产品需求文档 PRD V0.1（评审稿）

- 版本：V0.1-draft
- 日期：2026-11-17
- 阶段：需求分析 / 未经最终确认
- 产品名称（暂定）：Health — 个人健康记录与 AI 辅助就医助手
- 产品形态（建议）：移动优先 PWA；先个人使用，未来视验证结果扩展
- 核心表述：记录身体不适及处理经过，辅助识别明显危险信号，整理可信的就医沟通资料

## 1. 背景与问题

人在发生身体不适时往往难以持续记住具体时间、位置、症状、服药和变化过程；在就医时需要重新回忆、描述不完整。传统文本日记缺少直观部位定位、事件关联和可供医生快速理解的摘要。AI 可以帮助提炼和提示，但其错误可能带来延误就医、过度就医、虚假安心等风险。

## 2. 产品目标

1. 30–60 秒完成最基本的一次症状事件记录（目标指标，待测试）。
2. 同一事件按时间追加多条症状、服药、观察、就医记录；支持复发另建事件、历史关联。
3. 能通过正面/背面人体示意定位不适部位，处理无明确位置的症状。
4. 在用户提出分析请求或触发明确危险信号时，优先给出适宜的紧急行动提示，而非疾病定论。
5. 按事件或日期区间生成可复核的就医摘要（手机展示及 PDF 导出）。
6. 用户能掌控对 AI 和第三方服务的数据授权、删除和导出。

**非目标：** 诊断疾病、代替急救/医生、处方及药物剂量推荐、自动判断药物相互作用、医疗器械临床用途、医学影像诊断、监控/持续分析医疗设备数据。

## 3. 用户与场景

### 3.1 核心角色

- 主用户：自主记录并管理自己的健康信息，查看、补充、导出。
- 医生（非系统注册用户）：通过用户主动展示或分享的只读报告了解病程；不得默认获得账号或数据访问权限。
- 未来：家庭受托管理人、多档案；不属于 V0.1。

### 3.2 核心使用场景

A. 突然不舒服：点击人体图选择位置、选不适性质和程度，快速保存；若发现明显危险信号，先提示急救。  
B. 服药后：补充药物和实际服用剂量、时间，后续记录感受；不能自动推断因果或建议调整用药。  
C. 症状反复：在同一事件追加记录，或新建复发事件关联旧事件。  
D. 就医前：自动汇总时间线、位置变化、用药、检查及尚不明确事项，用户核对后导出。  
E. 无明确部位症状：使用“全身/不明确位置”或直接文字、语音入口，不能强制人体点选。

## 4. 关键概念与业务规则

- **健康档案 Profile**：用户资料、过敏信息（可选）、重要既往信息（可选）。
- **健康事件 HealthEvent**：一次连续健康问题的容器；可处于进行中、已结束；结束后仍可补记并保留时间戳和修订历史。
- **记录条目 EventEntry**：症状、用药、生命体征（手工）、就医、检查、备注、事件变化。
- **部位标记 BodyMark**：记录对应人体图版本、部位编码、左右侧、正背面、局部区域；位置可多个；可指示放射/延伸关系。
- **AI 分析 AIAnalysis**：仅代表某时点对特定记录快照的辅助说明；存模型/规则版本、输入范围、输出、生成时间、未决问题；不覆盖原始记录。
- **风险提示 RiskAlert**：由规则触发或 AI 提示的待复核危险信号，保存触发原因、规则版本、提示时间、用户反馈。风险提示与医学诊断严格区分。

**事件与条目的时间：** 分离发生时间、录入时间、更新时间；支持补记历史信息，保留时区。  
**资料可信度：** 区分用户自述、药盒/OCR 提取待确认、医疗机构文件、医师诊断（用户转录）与 AI 推断。  
**服药事实：** 记录“实际服用”“计划服用/医嘱”“未服用”不能混为一谈；名称、规格、剂型、单次剂量、单位、时间和备注应分字段。  
**数据删除：** 明确事件删除与账户删除规则，必要时短期恢复窗口，永久删除策略须经过隐私评审。

## 5. 关键用户流程

### 5.1 快速症状记录

首页“记录不适” → 选择身体位置（可跳过） → 选择症状/程度/开始时间 → 必要的高优先级危险信号检查 → 保存到新建/既有健康事件 → 选择是否进行 AI 补充问询 → 事件详情。

- 点击人体图不是必填；全身不适可直接记录。
- 提供“现在开始”“不确定开始时间”“补记过去时间”。
- 同事件允许多个症状及多个不同部位，不强制唯一主诉。
- 保存不得依赖 AI 成功；离线场景需可本地暂存或明确告知限制。

### 5.2 人体图选择交互

- 正面与背面切换；身体总体区域 + 二级局部分区；点击高亮并列出选中名称。
- 支持左右区分、多部位与取消选择，移动端保证触点尺寸。
- 以 SVG 资产/区域映射维护 body_map_version、zone_code、side、view、granularity；不同版本兼容既有标记。
- 特殊入口：全身性、体内不明确部位、无明显定位、文字补充。
- **视觉标注只是用户描述的定位，不代表器官诊断或医学解剖精度。**

### 5.3 用药记录

健康事件详情 → 添加用药 → 搜索/手工输入药名与规格 → 记录实际服用的剂量、次数和时间 → 可补充服用原因及反应 → 保存。  
药物识别/自动补全如未确认必须标记“待确认”；V0.1 不提供剂量推荐、停换药或交互禁忌判定。

### 5.4 AI 辅助问询与风险提示

用户发起分析或用户输入触发高优先级风险规则 → 规则独立执行 → 若命中急救危险信号，先展示行动提示，不等待 AI → 可选择后续非阻塞性补充问询 → AI 汇总“症状/已知与未知/需要评估的可能方向/就医行动建议” → 用户可查看每条推断对应的记录来源。

- 风险级别拟定：紧急求助 / 建议及时就医 / 未识别明确紧急信号（不等于安全）。
- 如无法获得充分信息，明确“不确定”，不能自动归为低风险。
- 风险引擎规则需医学专家审定、版本化、测试覆盖；在此之前仅能内部试用。
- 不提供疾病确诊概率、确定性治疗方案或独立用药建议。

### 5.5 就医报告

选择事件/日期范围 → 自动生成摘要草稿 → 用户编辑/隐藏敏感项 → 显示原始事实/医疗机构结论/AI 分析分别区块 → 生成手机可读报告及 PDF → 由用户主动分享。
报告至少含主要不适、时间线、身体标记、用药事实、相关检查、改善/恶化情况、待询问医生的问题及生成时间。支持“仅客观记录”模式，不必附带 AI 分析。

## 6. 页面范围

1. 首页：进行中事件、快速记录、最近用药/症状、查看报告。
2. 人体症状记录页：人体图、局部分区、多选标签、程度与时间。
3. 事件详情页：时间线、添加条目、状态、关联事件、生成报告。
4. 用药记录页：药物信息、实际服药情况、反应与关联事件。
5. AI 辅助页：问询、风险提示、依据、未知信息、人工纠正。
6. 就医报告页：报告预览、事实确认、隐私选项、导出。
7. 档案与设置页：基础信息、过敏史、数据授权与删除/导出。

## 7. 质量与验收原则

- 核心记录操作在 AI 不可用时仍可完成。
- 用户能够修正部位、时间、药名、剂量并保留更新痕迹。
- 主用户仅可见自己的真实数据；对 AI 发送敏感内容需明确告知与相应授权。
- 风险规则触发时，警示不被普通说明覆盖；未知状态不暗示无风险。
- 报告中的医学结论不得由 AI 伪造；文字分区明确资料来源。
- 关键操作形成安全审计记录，不在公共仓库或普通应用日志记录原始健康信息。
- 安全/隐私/法规与临床评审必须通过后，才可面向真实用户使用 AI 自动分诊。

## 8. 成功指标（试验目标，待基线验证）

- 核心症状录入中位耗时 ≤60 秒。
- 典型用户能在 3 步内进入症状记录。
- 90% 以上测试用户能不借助说明完成基本记录（可用性测试目标）。
- 就医报告每项医学事实可追溯到记录来源。
- 经专家确认的危险信号测试用例 100% 被正确优先提示（发版门槛；仍不能据此保证真实环境完全无漏报）。
- 零未授权跨用户访问作为安全验收门槛。

## 9. 关键风险与依赖

- 解剖区域划分不能代替临床定位；应做易用性测试。
- AI 错误与漏报带来现实伤害可能；需专业审核和验证集。
- OCR 识药可能产生名称/单位错误，必须人工确认。
- 真实医疗健康数据属于敏感信息，需数据最小化、单独同意、可撤回及加密存储。
- 公开项目仓库只能存设计资料与合成数据；用户真实医疗档案不得进入 GitHub。
- 部署区域、用户年龄、目标市场及第三方 AI 供应商可能影响合规实现。

## 11. 2026-11-17 需求迭代：就医后闭环与更细交互

本次已确认方向：继续深化人体图二级部位与 AI 补充问询设计；同时将医生开具的医嘱、治疗安排、实际治疗及用药执行纳入同一健康事件。详细业务规则见 [医嘱与治疗管理需求](./CARE-AND-ORDERS-V0.1.md)，交互更新见 [UX-SPEC](./UX-SPEC-V0.1.md)。

### 11.1 事件的扩展

一次健康事件不因完成就诊而结束。事件可关联多次就诊；每次就诊可形成多条医嘱/处方；每条医嘱可关联零到多条实际执行记录。医生建议或处方不能自动认定为患者已服药、已治疗、已做检查或已复诊。

### 11.2 就医与治疗流程（P0 范围）

1. **就医记录**：记录医院、科室、时间、医生意见及资料来源；用户转录的医生意见要明确标注，不能冒充正式医疗机构确诊。
2. **医嘱/处方**：记录医生建议、具体文本、医嘱类型及来源，允许关联就诊；可分别标注执行状态，但状态不替代实际执行条目。
3. **实际治疗**：时间、项目、过程/用户感受、可选关联治疗医嘱；同一医嘱允许多次执行。
4. **实际用药**：保留原有每次服药记录；可选关联处方/用药医嘱，未关联时也可作为独立事实保存。
5. **就医报告模式**：默认“就医前摘要”；额外提供“就医及治疗全程档案”，增加就诊、医嘱/处方、实际治疗和执行记录专区。

### 11.3 身体定位与问询深化

人体图从一级区域扩展二级部位（优先头颈、胸、腹、腰背）与可选放射/延伸位置关联；不能强制输入。AI 辅助页面原型使用**按健康事件症状/区域选择预设问题**的规则化交互展示，不调用大模型，不输出临床风险等级。真实 AI 动态问询及紧急分诊需独立医学评审后才可发布。

### 11.4 验收和非目标

- 不得将“医生建议服药”自动生成为“已经服药”；不得将“建议治疗”自动生成治疗执行事实。
- 报告必须注明医嘱来源，分别展示建议、执行情况和不确定状态。
- 首版仅需验证基本录入/关联/报告体验；多药处方结构化、签名验真、医院系统集成和 OCR 自动识别为后续深化功能。
- 当前 Public GitHub 仓库不得存放真实个人病历、医生医嘱原件、患者信息或密钥。
