# Health S1 研发验收记录（2026-11-17）

## 本轮锁定范围

- 本地 Worker + D1：创建健康事件、保存症状及人体位置、查询事件时间线。
- 独立的本地演示网页 \`/demo\`，不移植此前的七页原型。
- 标题、症状/部位等使用 AES-256-GCM 密文写入本地 D1；时间/类型等必要索引元信息仍保持结构化。
- 本轮无真实账户、生产部署、处方、用药、AI、OCR、正式就医报告服务。

### S1 API 集成实测的 15 项

1. 本地演示模式与无医疗分析标识。
2. 空事件标题被拒绝。
3. 客户端试图指定归属用户被拒绝。
4. 创建发生时间未知的事件。
5. 列表从 D1 重新读取刚创建的事件。
6. 不存在的事件返回 404。
7. 症状记录不依赖 AI。
8. 从密文解密事件时间线和身体位置。
9. 不合法的 11/10 不适评分被拒绝。
10. 头/腹等人体二级区域编码错误被拒绝。
11. 伪造医学机构核验来源被拒绝。
12. 错误的放射起终点引用被拒绝。
13. 被拒绝的请求未创建额外记录。
14. 处方接口明确不存在于 S1。
15. 同源联调网页可以通过本地 HTTP 读取。

## S1 结论

本轮核心本地 API 已能经过真实 HTTP + D1 集成测试并成功执行；它仍**不能给真实用户使用**。不要因“加密字段”和“固定演示档案”而误以为完成了生产级身份、权限、日志、密钥管理及合规要求。

截至本次验证，三项 CI 作业均已成功。下一步是代码评审并确认本地启动步骤；安全阶段门继续关闭，S1 Draft PR 暂不自动合并。
