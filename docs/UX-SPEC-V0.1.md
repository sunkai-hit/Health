# Health V0.1 交互设计说明（UX Spec，评审稿）

- 状态：初版原型已实现（对应 \`prototype/v0.1/\`），部分交互仍属于待设计项。
- 定位：移动优先、低操作负担、健康事件为中心、医学风险提醒以安全为第一约束。
- 范围：只定义 UI 和用户体验，不代表任何临床分诊规则通过审查。

## 1. 信息架构

\`\`\`mermaid
flowchart LR
H[首页] --> R[记录不适]
R --> B[人体区域选择]
B --> S[症状描述]
S --> E[健康事件]
H --> E
E --> M[添加实际用药]
E --> A[AI辅助问询]
E --> P[就医摘要报告]
P --> X[打印或导出]
\`\`\`

原型包含六个页面：首页、记录不适、健康事件、用药记录、AI 辅助、就医报告。账户/档案及隐私设置已列入需求 P0，但本次尚未实现。

## 2. 记录页的三阶段交互

### 2.1 阶段 A：定位位置（可跳过）

**已实现**

- 2D 简化人体图正/背面切换。
- 点击身体区域标亮、再次点击取消；所选区域以可删除标签列出。
- 多部位同时选中；两个视角的标记保留在同一记录中。
- 左右方向以用户本人身体为准，观看者视角与人体左右相反。
- 提供“全身不适 / 说不清具体位置”入口。开启该模式时清除具体位置标记，避免互相矛盾。

**下一轮需细化**

- 一级区域 → 二级局部 → 精细位置选点（如胸骨后、上腹中部、右下腹），不可用单个热点代表器官。
- 放射/牵涉方向标记（从 A 位置延伸到 B 位置）。
- 人体图缩放、区域无障碍语义、文字列表等价入口；应完成不同屏幕点击热区可用性测试。
- 身体部位映射采用 zone_code、body_map_version，历史报告保留快照。

### 2.2 阶段 B：描述症状

**已实现**

- 症状标签多选（疼痛、胀痛、刺痛、酸痛、麻木、瘙痒、恶心、头晕、乏力、其他）。
- 主观不适程度 0–10。
- **默认未评分**：不应把滑块的视觉默认位置当作实际症状数据；只有用户明确启用并调整/确认后才保存评分。
- 开始时间（允许补记）、自由文字描述。
- 不要求部位/症状标签都填写，但至少有一种有意义的记录内容。

**下一轮需细化**

- 持续/间歇、首次/复发、伴随症状、变化趋势与影响日常活动等可选字段。
- 时间不确定或仅记得大约时段的表达。
- 错误输入、未来时间、重复记录等校验。
- 语音信息提取与用户确认（P1）。

### 2.3 阶段 C：关联健康事件

**已实现**

- 保存时新建健康事件或加入已有事件。
- 新建事件名称可手动确认/修改。
- 同一事件可添加多条记录、按发生时间展示；可以标记“已结束”。
- 新记录立即进入事件详情和就医报告，无需 AI 参与。

**下一轮需细化**

- 自动识别可能关联事件只做建议，用户必须确认；不能自动把不同疾病合并。
- 事件修订、编辑、删除、回滚；标记记录来源与补记情况。
- 从多个正在进行的事件中更清晰地选择关联目标。
- 症状、用药与就医记录的相互关联及原因字段。

## 3. 用药记录设计

**已实现**：药名、实际服用量及单位、时间、关联健康事件、服药后自述感受；加入时间线、报告与用药汇总。

**下一轮待设计**：
- 药品通用名、商品名、包装规格、剂型、药品图片/药盒 OCR（P1）。
- 用药状态（计划/实际服用/未服用/不确定）、服用途径、医嘱来源。
- 记录原始填写方式，不允许通过片数无依据换算 mg。
- 无法确定药名/剂量时显示“不确定”，不能 AI 猜测。
- 长期规律用药与某次事件临时用药是否分开管理。
- 用户描述用药后变化只是时间上的关联，不代表明确因果关系。

## 4. AI 辅助体验

**已实现**：固定问答演示、允许“不确定”的选项、完成后显示全部答案；可打开独立的紧急提示样式模板（明确与用户当前症状无关）。

**未实现（需要前置审核）**：
- 根据事件上下文动态补充问询。
- 独立危险信号规则引擎、规则版本和优先级协调。
- 面向用户的实际风险等级及行动建议。
- 生成式 AI 的非诊断性解释、来源引用及更新控制。
- 医学审核、法规判断和安全测试。

### AI 页未来应呈现的四个状态

1. **问询中**：只问对当前记录有意义的缺失信息，已有数据不重复询问。
2. **紧急提示**：经过审核的紧急规则命中立即显示，不等待大模型。提示为可理解的行动要求。
3. **无法评估**：缺失关键资料、模型失败或网络中断时，不显示“低风险/安全”结论。
4. **分析摘要**：以用户记录事实 → 信息缺口 → 可能需评估的方向 → 行动建议顺序展示；禁止伪造确定诊断及用药指令。

## 5. 就医报告页

**已实现**

- 按当前选中健康事件自动汇总。
- 展示事件名称、开始时间、状态、涉及症状区域（含正反小图）、时间线、实际用药。
- 可选附加 AI 功能说明；默认不含 AI 附录。
- 可复制纯文字报告；通过浏览器打印另存 PDF。
- 报告清楚说明来源为演示记录，不能解释为医学诊断。

**下一轮需细化**

- 用户预览、逐项编辑/隐藏敏感段落再导出。
- 医院/科室/医生意见/检查单独分区并标明来源。
- 报告按事件或日期范围筛选；支持多次事件对比。
- 固定版式、生成时间与记录快照版本；打印分页、中文字体兼容性。
- 医生视角测试是否能快速找到症状时间、药名剂量及关键信息缺口。

## 6. 页面状态清单

| 页面 | 正常状态 | 空白/异常/特殊状态 |
|---|---|---|
| 首页 | 有进行中事件与统计 | 首次使用无事件 |
| 记录不适 | 人体图 + 症状信息 | 位置不明确、未评分、无法确定发生时间 |
| 健康事件 | 多条记录时间线 | 无记录、多个并行事件、结束后补录 |
| 用药记录 | 实际服药明细 | 不明药名、未知剂量/规格、未服药 |
| AI 辅助 | 问询和说明 | 已命中紧急规则、缺信息、服务失败、用户不授权 |
| 就医报告 | 完整事件摘要 | 条目不全、来源未核实、用户隐藏敏感信息、PDF 失败 |

## 7. 验收路径（合成数据）

- **路径 1**：新建“头痛”事件 → 正面选头 → 选择疼痛 → 保存 → 查看时间线 → 报告体现位置。
- **路径 2**：现有腹部事件 → 补录不同日期症状 → 加入用药记录 → 按发生时间展示，事实和用药分离。
- **路径 3**：用户全身乏力 → 不选身体区域 → 直接记录 → 报告不显示虚假的具体定位。
- **路径 4**：没有不适程度评分 → 保存 → 报告展示“未评分”，不能默认为 5/10。
- **路径 5**：AI 模拟问询选择“不确定” → 仅显示已答内容，不生成个人疾病或风险等级。
- **路径 6**：生成报告 → 可以复制或打印；只有用户操作才开始分享。

- D-09：报告默认是否仅包含事实资料？

## 9. 2026-11-17 交互迭代增补

**人体图二级选择（原型已实现局部区域）：** 点击人体一级区域后出现“整体区域 / 二级细分区域”选项。选择二级位置时移除该一级“整体”标记，避免重复计数；可同时选择同一部位多个二级位置。对没有二级定义的部位保留整体选择。支持选中两个已标记的位置，记录“从 A 延伸到 B”，只作为本人描述，不作为医学诊断推断。二级字典当前不完整，需下一轮补齐全部主要身体部位并验证点击精度。

**事件感知 AI 问询样例：** 根据当前事件的自述症状/部位，在腹部、头颈、胸部、四肢等分支中选择不同的预设问题；允许“不确定”。这是为了验证 UI，**不是大模型，不进行临床风险分层**。正式分诊必须完成独立医学审核、规则版本控制和异常流程测试。

**新增就医与医嘱页面：** 通过独立三个标签录入：就医记录、医生医嘱/处方、实际治疗执行。用药记录新增“关联某条医生处方”选项。健康事件时间线按发生时间展示不同类型条目，且显式区分“医生建议 / 实际执行”。

**报告双视图：** 
- 就医前摘要：症状、部位、实际用药、既往主要事实、问诊待核对问题。
- 就医与治疗全程档案：上述内容加就医记录、医生医嘱/处方、实际治疗和用药执行明细。医生转录信息标注来源与核验状态。

**原型尚未完成：** 处方多药明细结构化、原始医院文书附件、医嘱修改/撤销、条目编辑、报告隐藏敏感字段、精准点位缩放、动态临床问询与实际 AI 引擎。不能将原型表单解释为已具备安全可上线能力。
