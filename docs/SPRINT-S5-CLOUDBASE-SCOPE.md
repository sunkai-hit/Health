# S5｜CloudBase 无服务器/无自有域名测试基线

日期：2026-11-18
分支：\`feature/mvp-s5-cloudbase-dev\`
范围状态：**锁定，只有本地代码和模拟验证，不会自动创建云环境或部署**

## Sprint 目标

解决“已有微信小程序 AppID、但无自有服务器和 HTTPS 域名”的开发阻断。使用微信·云开发方案，建立一个**显式启用、默认关闭**的虚构数据云函数连接演示。

| 功能点 | 本轮交付 | 验收 |
|---|---|---|
| S5-01 | CloudBase 决策文档/地域与备案阶段门 | 不将服务器/域名采购作为测试阶段前提 |
| S5-02 | \`miniapp/config/cloud-env.js\` 默认关闭 | 未配置环境时，无 CloudBase 初始化和远程调用 |
| S5-03 | \`healthDevPing\` 静态云函数 | 不处理请求中的个人身份字段、不保存数据 |
| S5-04 | 云连接测试页 | 未启用时按钮不可点击；手工测试环境配置之后才能请求 |
| S5-05 | 自动化断言和 CI | 维持 S1～S4 全量回归，新增云开发闸门测试 |
| S5-06 | 上线条件清单 | 无备案/安全/账户验证时不得录入真实健康资料 |

## 本轮明确不做

- 购买/配置服务器、HTTPS 自有域名或开发云数据库集合
- 开通云开发平台和部署云函数（需要用户本人账户授权及环境 ID）
- 真实登录/OpenID 写入、用户注册、个人档案、用户会话
- 健康数据写入、上传真实报告、文件存储和云数据库权限
- 医嘱/处方/AI/OCR/家庭档案；不修改任何原有业务需求

## 缺陷处理策略

- **S5 阻断**：默认未配置却访问云端、测试函数返回个人信息、客户端出现 AppSecret/session_key、CloudBase 不可控地写入数据库、CI 失败。
- **后续集成**：用户创建云开发测试环境并验证小程序 AppID 关联后，才允许手工云函数部署与真实调用验证。
- **正式发布阻断**：小程序备案与类目、地域和平台安全规则、敏感健康信息单独同意、KMS 和数据删除/审计。
- **范围外**：其他产品能力保持排队。

不以“测试环境已联通”代替“正式身份/健康数据可用”。


## 环境 ID 到位后的约束变化（2026-11-18）

项目方已提供 `health-d2gxjb20h1d33fa91`。本分支现在将 `cloud-env.js` 设为 `enabled:true`，仅用于测试环境 SDK 初始化；`purpose` 明确限定为 `synthetic-ping-only`。**仅用户点击测试按钮才会调用 `healthDevPing`**。

此前“默认关闭、空环境 ID”是环境未到位时 S5 基线的历史状态。此更改不引入生产身份、真实医疗信息写接口、数据库或自动云请求。实际关联与函数部署依旧需要由拥有 AppID/CloudBase 权限的项目方在微信开发者工具中手工完成。
