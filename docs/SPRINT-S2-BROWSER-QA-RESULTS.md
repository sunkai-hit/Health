**S2-QA-B01：快速切换身份出现旧请求覆盖新状态。** 在进入页面后初始用户 A 的 \`/dev/session\` 请求被延迟时，用户切换到 B，B 的结果先返回并正确展示；随后迟到的 A 结果覆盖当前演示令牌与界面，将标签显示改回 A。这在桌面与移动视口均复现。

此现象属于**界面异步身份状态竞态**；它不意味着服务端 A/B 对象级授权被绕过，但若不修正，可能在同一浏览器页面将用户界面与其当前选择的身份错误对应。属于 S2 QA 阻断。

### 最小修复

- 文件：\`src/mvp/demo-ui.ts\`
- 每次切换虚构身份递增 \`identityEpoch\`。
- 异步 \`/dev/session\`、\`/me\`、事件列表和时间线响应渲染前确认仍属于最新身份版本；旧请求返回直接丢弃。
- 切换期间禁止新的事件创建、症状提交和手动列表刷新，防止数据操作跨切换乱序。
- 正在进行的创建/症状操作若遇到身份切换，其迟到的响应不能再更新当前界面。
- 将“共用一个固定档案”的误导性演示提示改为“两个相互隔离的虚构档案”。
- **未改后端业务对象、未增加产品功能、未引入真实登录或新部署依赖。**

## 三、新增的六类浏览器场景（两种视口均成功）

1. 本地虚构 A 登录初始化；不向 LocalStorage、SessionStorage 或 Cookie 持久化签名令牌，缺令牌直接请求事件资源得到 401。
2. A 新建事件后切到 B 看不到该事件；B 新建独立事件后切回 A，也无法看到 B 的事件；再次切 B 验证完整。
3. 症状及一级人体位置记录在 A 下；切换 B 后不显示 A 的症状，再切回 A 可以恢复。
4. 页面刷新后重新领取虚构短期令牌，本地加密 D1 中的事件依然存在，且令牌不写入长期浏览器存储。
5. 含有 HTML 特殊字符串的虚构事件标题只按文本显示，不创建动态 HTML 元素。
6. 人为延迟初始 A 的发令牌请求，随后快速切到 B；A 的过期响应不能把界面恢复成 A。

## 四、明确未完成

- **真实 Android/iOS 实机**、更多浏览器、辅助技术与弱网可用性，仍然没有进行。
- **真实身份认证未实现**：本地可以任意申请 A 或 B 的演示令牌，不能代表用户真实身份。
- KMS/密钥轮换、合规数据驻留、敏感信息单独同意与数据删除机制仍未实现。
- S2 API 仅验证当前的虚构 A/B 对象隔离，不代表系统完成生产安全测试或抵御全部应用攻击。
- 处方/实际用药/治疗、AI/OCR、家庭档案、服务端报告均不在本轮范围，不因验收成功而进入 S2 开发。
