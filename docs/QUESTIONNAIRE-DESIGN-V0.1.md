# Health V0.1 按事件自适应问询设计（需求与安全评审稿）

> 本文件设计**问询体验与算法边界**，不是实际临床分诊知识库。现有浏览器原型通过预设问题集演示动态变化，未连接大模型、未根据症状输出紧急等级。

## 1. 问询产品目标

- 避免首次记录要求填写十几项；只补充**当前事件对完整病程有帮助**的问题。
- 优先复用人体图、症状标签、发作时间、程度和近期记录；已明确且可信的数据不重复询问。
- 问题数量有限，任何阶段可跳过、选择“不知道”、取消或直接保存记录。
- 遇到明确的医学紧急危险信号时，**未来审核过的规则模块**应立即提示用户寻求紧急医疗帮助，且不受生成式问答等待影响。
- 生成的是症状记录和就医准备信息，不能伪装成诊断结论或医疗处方。

## 2. 两条互不混淆的链路

\`\`\`mermaid
flowchart TD
    A[用户主动记录] --> B[事实结构化]
    B --> C[经审核的安全危险信号规则]
    C -->|严重信号已证实触发| D[立即展示急救行动提示]
    C -->|尚无已证实触发/信息不足| E[补充问询（非诊断）]
    E --> F[用户回答并确认记录]
    F --> G[事实性事件摘要]
    G --> H[可选 AI 文字整理]
    H --> I[就医报告草稿]
\`\`\`

规则引擎结果和 AI 摘要应分别存储；AI 不能删除危险信号、降低风险级别或改变医嘱内容。缺少信息或规则失败只能进入“不确定/无法评估”状态。

## 3. 问题分层

### 3.1 基础信息（通用问题）

- 开始：何时出现、突然还是逐渐。
- 持续：一直存在、反复出现、不确定。
- 变化：加重、减轻、无变化、不确定。
- 伴随表现：由用户自由描述或选择预设标签。
- 是否有影响日常活动：作为用户自述，不据此直接排除危症。

### 3.2 部位/症状相关（首版演示，不是诊断路径）

| 场景 | 预设问题示例 | 记录目的 |
|---|---|---|
| 腹部不适 | 与进食前后是否有时间关系 | 帮助复述发作过程 |
| 头颈不适 | 主要位置是否发生变化 | 帮助描述部位趋势 |
| 胸部不适 | 是否影响平时活动 | 收集描述，不排除危症 |
| 肢体或腰背不适 | 与身体活动是否有关联 | 收集时间关系 |
| 位置不明确 | 持续/间歇、变化方向 | 避免强制人体定位 |

**注意：** 这些只用于演示问询界面的分支与状态，不能据此给出任何个性化急症排除、疾病概率或医疗处置建议。

### 3.3 后续医学审核后的增补

需医学人员针对**适用人群、主诉范围、危险信号、关键问题、时效阈值、组合判断、否定语境、矛盾信息**逐条审查、建立用例及部署开关；在未达到临床和监管阶段门前，面向真实患者的自动风险等级功能必须保持关闭。

## 4. 问询协调策略

1. **识别当前事件**：使用健康事件 ID、症状条目、部位标记，以及用户本次同意的数据范围。
2. **形成缺口**：按最小问题集优先级选下一问题；每条问题必须标明其帮助补充的业务字段。
3. **问题数量**：用户体验目标每轮 2–4 个重点问题，可跳过；总问题数应通过可用性测试确定。
4. **回答形式**：优先选择题与“其他/不知道”，必要时文本或语音；否定词须准确保存。
5. **保存与再进入**：答案成为用户确认的症状条目，不是独立疾病结论；再次进入只追问发生变化或以前缺失的信息。
6. **失败状态**：模型不可用、信息不足、超时或用户拒绝授权时仍可继续记录；不因此输出“安全”级别。
7. **审计与追溯**：保存问题模板版本、选择依据、回答时间及用户确认状态；医学规则另存版本、触发条件及警示展示时间。

## 5. 输出 UI 四类状态

- **事实确认卡**：你已经记录了什么，允许修改；不夹杂 AI 推测。
- **补充问题卡**：清楚说明为什么需要这个问题，可以跳过。
- **分析不足卡**：没有足够信息，不能确定；必要时建议联系专业医疗人员，不显示虚假的低风险。
- **紧急提示卡（仅医学审核后启用）**：明确应采取的及时行动，屏蔽“继续完成问答才能查看”的障碍。

## 6. 反面用例（首版必须规避）

- 将“胸部不适但不是胸痛”直接判定没有风险。
- 将否定描述如“没有呼吸困难”漏掉“没有”二字。
- 用户说“不知道”却被系统自动归入“没有症状”。
- 将上次事件服药记录自动当成此次事件已服药。
- 将医生开具的处方当成患者已经服药的事实。
- 没有任何医学审核的情况下展示“当前低风险/无需就医”。
- 在收到就医记录附件时让 OCR 文本覆盖用户实际填写事实或医疗风险规则。

## 7. 设计交付物与评审门槛

- 预设问题库及其字段映射、原型分支与状态图；
- 问询答案与事件记录的关系，以及用户更正流程；
- 临床审核后的危险信号规则与覆盖测试清单；
- 模型服务数据授权和最小化处理方案；
- 与医嘱/治疗数据来源的隔离：AI 不从医嘱文本中生成自行服药行为；
- 基于合成案例执行的可用性测试结果。

上述前两项可以在原型阶段推进；风险分级、临床建议与医学规则发布需要后续专业评审和安全验收。
