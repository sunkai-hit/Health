# ADR-0002｜中国大陆微信小程序：无需自购服务器/域名的 S5 云开发测试方案

日期：2026-11-18
状态：**研发默认方案，未开通真实云环境，未通过真实用户发布审查**

## 已确认基础条件

- 中国大陆首批用户、微信原生小程序
- AppID：\`wx027f1a9c66e3c01a\`（用户提供；仍需核实主体/管理权限）
- **用户尚无云服务器、自有 HTTPS 域名**
- 产品 S1～S4 仅虚构数据研发，禁止真实个人健康数据

## 决策：先采用微信·云开发（CloudBase）的受控测试环境

不为了 S5 购买服务器和自有域名。原生小程序可通过 \`wx.cloud.init({ env })\` 关联环境，使用 \`wx.cloud.callFunction({ name })\` 直接调用云函数，**不依赖自有 HTTPS API 域名或自建登录服务**。

**明确不混用两套身份体系：**
1. **微信·云开发的小程序调用路径**：调用身份由微信平台传递到云函数；后续若需要识别用户，在云函数中验证可信的调用上下文，映射内部用户档案。当前 S5 测试函数不读取任何身份。
2. **独立 HTTP API / 自建服务路径**：按早期 ADR-0001 的 \`wx.login → code2Session → Health 会话\` 方式实施；**暂不作为小程序首发必需的架构**。保留原 code2Session adapter 仅作备选，不删除既有实现。

后续如果引入 H5/PC/跨平台服务，才重新评估独立后端和 OAuth/OIDC 等身份方案。

## 关键风险与约束

- 微信小程序 AppID 必须与 CloudBase 环境关联；未关联环境会报访问错误。
- **小程序备案仍然需要完成**；没有自有 HTTPS 域名不等于免小程序备案。未来如果转自定义 API 域名，则另外办理合法域名配置及相应备案。
- 云开发服务仍有使用费用或配额、账号管理、地域和平台服务条款；不保证免费，不视作已开通。
- 试验环境优先选择**中国大陆可用地域**，并检查数据保存地域、日志/备份、权限和相关合同。未核验这些之前不可导入患者数据。
- 云函数访问上下文仍需服务端校验、严格区分小程序来源、避免恶意客户端参数伪造用户身份；官方明确提醒在多调用来源和实例复用时 \`getWXContext\` 可能产生身份错配，因此**S5 不依赖 \`getWXContext\` 或存储 OpenID**。
- **禁止小程序直接对健康文档集合执行宽权限数据库 CRUD**。未来真实健康资料必须通过审查的云函数访问、逐对象权限、单独同意、密钥管理、操作审计和导出删除路径。
- 微信云开发的身份透传并不替代个人信息保护法对医疗健康等敏感信息的合法处理要求。

## S5 范围锁定

- 原生工程新增云开发环境开关，仓库默认 \`enabled: false, envId: ''\`；没有环境时绝不发请求。
- 新增 \`miniapp/cloudfunctions/healthDevPing\`，只返回固定布尔状态，不读取身份、不访问数据库、不开写接口。
- 新增 \`pages/dev-cloud\`，仅在显式开通测试环境后可点击检查云函数连通性。
- 静态测试与模拟运行时测试覆盖默认关闭、无凭据、本地非启用不出网、错误响应失败关闭。
- 不部署云函数，不创建云数据库集合，不保存真实健康记录。

## S5 之后的最少外部前置

1. **在微信开发者工具里开通一个独立云开发测试环境**，账号具有 AppID \`wx027f1a9c66e3c01a\` 的管理/开发权限。记录环境 ID 与选定中国大陆地域。环境 ID 本身不是 AppSecret。
2. 在云开发平台把上述 AppID 关联该环境，仅手工上传 \`healthDevPing\`。
3. 用开发者工具/测试号打开原生小程序，实测 \`wx.cloud.callFunction\`，只处理虚构数据。
4. 上线前另行完成小程序备案、类目/资质、敏感信息处理告知、独立同意、存储/加密/KMS、导出删除和安全验收。

**注意：这条路线不意味着已经拿到可生产处理医疗数据的安全资格。**
