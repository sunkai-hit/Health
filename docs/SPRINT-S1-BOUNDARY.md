# Health Sprint S1｜最小业务闭环与需求收敛

- 状态：开始研发；只支持虚构数据的本地演示 API
- 分支：\`feature/mvp-s1-core\`（从 \`docs/requirements-v0.1\` 建立）
- 原则：一轮只解决一条主链路；新增诉求先判断是否阻断本阶段验收
- **交付目标**：事件创建 → 症状及人体部位录入 → 事件时间线查阅，数据存入本地 D1；原始症状和标题使用 AES-GCM 加密载荷。

## 一、本轮范围（锁定）

| 功能 | 本轮范围 | 验收 |
|---|---|---|
| S1-01 本地演示启动 | 显式开启 localhost 模式，随机生成本地演示加密密钥 | 默认未配置拒绝访问；不会开放生产路由 |
| S1-02 健康事件 | 创建、列表、详情；标题、发生时间精度 | 可跨页面刷新继续从本地 D1 读取 |
| S1-03 症状记录 | 症状标签、说明、严重度可空、开始时间/未知、位置标记 | 插入数据库；事件详情可还原 |
| S1-04 人体位置编码 | 正/背一级区域及少数二级区域，位置编码校验、放射关系校验 | 非法编码返回 422 |
| S1-05 数据安全最小边界 | 本地演示账户、服务本机使用限制、应用层 AES-GCM、数据库写事务及审计最小信息 | 无密钥或非 localhost 时拒绝使用 |
| S1-06 联调页面 | 只提供创建事件、填写症状及查看时间线的简洁页 | 使用同一个 API 和本地 D1 |
| S1-07 CI | TypeScript 编译、D1 迁移、API 集成测试、原有 Playwright 回归 | 自动运行且有通过日志 |

## 二、本轮明确不做

- 真实用户注册、登录、多档案、数据同步、公开服务或生产部署
- 医嘱、处方、实际服药、治疗、复诊的正式 API（保留已确认 PRD/原型，不在此轮实现）
- AI 问询、医学风险判断、OCR、附件、通知、PDF 服务端生成
- 密钥轮换、KMS、完整敏感数据保护/删除、用户授权处理（下一安全阶段门）
- 全量 2D SVG 原型移植到后端页面；旧原型功能不受影响
- 处方领域模型重构、家庭模式、健康趋势、临床风险规则

这些功能不因现有原型已出现相关按钮就自动成为 S1 开发任务。

## 三、问题收敛与验收门槛

- **P0 本轮阻断**：无法跑起来、字段事实错误、真实健康信息泄漏、跨事件引用未校验、虚构数据未加密、错误输入被误写入、CI 不通过。
- **P1 下一迭代**：事件编辑删除、真实登录与数据隔离、复杂症状与全部二级区域、正式 PWA 页面、处方接口。
- **P2 暂缓**：多家庭成员、AI 自动诊断/分诊、OCR、长期用药智能分析等。

开发中发现问题先形成「重现 → 影响 → 最小修复 → 自动测试」记录。非阻断问题创建 Issue 归档，禁止在 S1 里临时扩大模块。没有通过 API 的实际集成测试前，不宣布 S1 完成。

## 四、边界安全说明

\`DEMO_MODE=local\` 与本机主机名校验只用于研发演示，它不是正式身份认证；每次测试都共享固定虚构档案。所有输入应为虚构材料。

虽然敏感文本使用 AES-GCM 加密，但目前不具备生产 KMS/密钥轮换、用户认证/授权、法定隐私告知等关键能力。不得部署为真实健康记录服务，不得输入真实健康信息。生产 API 必须重新引入真正用户身份与逐对象所有权检查。

## 五、运行目标

\`\`\`bash
npm install
npm run dev:setup
npm run db:migrate:local
npm run dev:api
# 浏览器访问 http://127.0.0.1:8787/demo
\`\`\`

本地数据库保存在 \`.wrangler/\`，演示密钥保存在 git 忽略的 \`.dev.vars\`。若遗失本地密钥，旧加密数据不可解密，需重置**仅限虚构数据**的本地数据库。严禁将此行为用于真实用户数据。
