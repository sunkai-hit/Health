## 二、浏览器已覆盖的九类场景（两个视口均通过）

1. 初始页面和演示数据加载，无 JS 页面错误、无浏览器本地持久化。
2. 点击人体一级部位，选二级细分区域，保存新症状并形成健康事件。
3. 多药处方新增药品项、表单草稿保留、保存展示。
4. 实际服药关联某张处方的特定药品项，在全程报告呈现。
5. 复诊计划与实际就诊分离，独立登记就诊后关联数量变化。
6. 新医嘱替代旧医嘱，旧版文本在时间线中保留。
7. 图片本地预览，不进行 OCR，刷新即丢弃。
8. 用户录入 HTML 特殊文本时转义显示，避免被当作标签执行。
9. 初始首页无明显横向溢出。

## 三、SQLite 已覆盖的八类场景

1. 数据表集合完整。
2. 初始迁移可重复执行。
3. 不存在的档案不能创建关联事件。
4. 处方及药品明细不会自动生成实际用药记录。
5. 不合法的用药状态被数据库拒绝。
6. 新版医嘱不覆盖旧版医嘱内容。
7. 同一条医嘱不能替代自己。
8. 附件所属关系及负数大小校验。

数据库迁移只是结构草案，敏感内容字段以 \`BLOB\` 表达**需要应用层加密的载荷**，当前 SQL **并未实现密钥管理或实际加解密**。SQLite 本身的外键不会替代跨用户授权和同事件引用校验；这些属于服务端 API 待开发内容。

## 四、尚未验证的方面

- 真实 Android/iOS 设备操作、不同系统浏览器、键盘读屏/无障碍、弱网和离线策略。
- 全部身体区域二级选择的覆盖与医学表达准确性。
- 多事件情况下所有关联和编辑/删除/撤销历史的完整一致性。
- 正式用户注册登录、对象级权限、账号隔离、身份会话、数据导出和删除。
- 真实附件上传、私有存储、医疗文书 OCR、用户逐项确认。
- AI 模型对个人资料的处理、危险信号规则、医疗安全评审及监管检查。
- 生成 PDF 的完整页眉/分页、长内容报告、可访问性、源数据确认和不可变快照。
- 生产数据库部署、应用层加密、密钥轮换、备份恢复、日志脱敏、跨境审查。

**因此当前项目状态：原型核心自动化测试通过；尚未满足真实个人健康数据上线要求。**

## 六、自动化入口

- \`package.json\`：\`npm run check:js\`、\`npm run test:prototype\`、\`npm run test:db\`
- \`playwright.config.mjs\`：Chromium 和移动视口测试配置
- \`tests/prototype.spec.mjs\`：九类浏览器场景，每类在两个项目运行
- \`db/tests/test_schema.py\`：八个 SQLite 单元测试
- \`.github/workflows/prototype-e2e.yml\`：对 PR/指定分支变更自动运行

建议在正式研发启动前提交依赖 lockfile，并将权限与数据保护的自动化测试纳入 CI 阶段门。
