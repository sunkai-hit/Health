# Health S2 QA 补强：双虚构账号真实浏览器验收（固定范围）

**目标：关闭 S2 留下的“演示页还没有浏览器 E2E”缺口。** 本轮仅增加本地 Worker + D1 的 UI 测试与暴露问题的最小修复，不扩展已批准的产品功能。

## 本轮仅包含

- 新增专用 Playwright 配置 \`playwright.mvp.config.mjs\`，自动启动本地 Worker、连接本地 D1，Chromium 1280px 桌面与 390px 移动视口运行；
- 测试 A/B 身份切换后事件列表与症状时间线隔离；
- 检查刷新后虚构事件仍在本地 D1、演示令牌不写 localStorage/sessionStorage/Cookie；
- 检查输入 HTML 类文本只能作为文字显示；
- 检查快速切换时过期的异步响应不会把当前 B 的界面改回 A；
- CI 增加独立 \`mvp-browser\` 作业，不破坏旧原型的测试和 S1/S2 API 测试；
- 发现错误优先修最小问题，添加对应测试验证。

## 严格不包含

- 真实注册登录、手机号/OIDC、KMS、安全合规认证、生产部署；
- 处方、治疗、实际用药、AI、OCR、家庭档案、正式报告；
- 复杂的跨设备/多人协作、离线持久化或全功能 PWA 重写。

**本机 A/B 演示令牌可任意领取，仍然不是正式身份认证，也禁止真实个人健康数据。**

## 验收条件

1. 新的本地 Worker 浏览器测试在桌面和移动模拟视口全部成功；
2. 原有 S1/S2 API 27 项、SQLite 8 项、旧原型 Playwright 18 项均保持成功；
3. 如果发现请求竞态或数据串号，只修复身份切换的异步过期结果处理，不扩大业务范围；
4. 记录 CI 运行链接、通过项、修复项及仍未覆盖的风险，保持 Draft PR 待评审。
