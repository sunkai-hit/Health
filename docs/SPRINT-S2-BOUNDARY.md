# Health Sprint S2｜虚构身份与数据归属校验

- 日期：2026-11-17
- 分支：\`feature/mvp-s2-identity\`；基于 S1 \`feature/mvp-s1-core\`
- **范围状态：锁定**；本轮仅在本地虚构数据演示 API 上验证身份传递与对象归属
- **非产品声明**：这不是正式登录，不可处理真实个人健康数据，不可部署外网

## 1. 本轮唯一业务目标

延续 S1 的“创建健康事件 → 记录症状 → 查看时间线”，增加两名虚构演示身份 A/B，验证服务端能按身份隔离事件和症状。

\`\`\`mermaid
flowchart LR
    L[本地演示身份 A/B] --> T[签名短期演示令牌]
    T --> M[Worker 签名和期限验证]
    M --> C[服务端确定用户与档案归属]
    C --> A[事件列表与详情过滤]
    C --> B[事件症状的写入与读取]
    A --> D[(本地 D1)]
    B --> D
\`\`\`

## 2. 锁定功能及验收口径

| ID | 工作内容 | 验收标准 |
|---|---|---|
| S2-01 | 双虚构身份 | 仅有 \`alice/bob\` 两种固定测试身份；同名账号不对应任何真实人员 |
| S2-02 | 本地短期签名令牌 | 随机本地 256 位 HMAC 签名密钥；令牌含发行方、使用对象、主体与 15 分钟有效期 |
| S2-03 | API 入站身份检查 | 缺失、篡改、过期、非预期 audience 的令牌均返回 401 |
| S2-04 | 服务端决定 owner/profile | 客户端传 \`owner_id\` / \`profile_id\` 等字段不获信任；新记录归属来自已验证虚构主体 |
| S2-05 | 跨用户隔离 | 用户 B 看不到 A 的事件列表、直接访问 A 事件 ID 返回 404、不能查询或增加 A 的症状；反向同理 |
| S2-06 | 本地切换体验 | \`/demo\` 切换 A/B 后重新签令牌；仅保存在页面变量，不进 LocalStorage/Cookie |
| S2-07 | 回归和关闭 | TypeScript、本地 D1 迁移、API 负面测试和原有 Playwright/SQLite 测试在 CI 通过 |

## 3. 审慎的安全界限

### 演示身份的局限

- \`POST /api/v1/dev/session\` **允许任何本地演示者选择 A 或 B 领取有效令牌**：它仅用于模拟已认证身份的后续权限检查，不具有身份证明能力。
- API 仅在 \`DEMO_MODE=local\` 且 localhost 条件满足时提供；\`workers_dev=false\`、无公开路由；这属于研发防误用约束，不等于生产认证。
- Bearer 令牌存于联调页 JS 闭包变量，不写 \`localStorage\`、URL、Cookie、应用日志；刷新后重新申请。
- HMAC 密钥保存在 git 忽略的 \`.dev.vars\`，由 \`npm run dev:setup\` 生成，不是正式密钥管理系统。
- S1 的业务加密密钥单独保持，S2 增加独立演示令牌签名密钥；依然没有生产 KMS、密钥轮换、备份/恢复和正式用户身份提供方。
- 不能向产品、客户或测试者宣称“已经实现了正式安全登录”或“已经达到真实病历存储的合规要求”。

### 必须拒绝的操作

- 无有效 Bearer 令牌访问事件列表/详情、症状列表/创建。
- 用虚构 B 的令牌访问或追加虚构 A 的事件。
- 客户端指定 \`owner_id\` / 伪造可信医疗来源。
- 非预期 API、没有明确支持的医嘱/处方/AI/OCR 请求。
- 任何公开部署或真实个人健康数据的使用。

## 4. 本轮不做

- 真实账号注册、手机号短信、微信登录、OAuth/OIDC、SSO、密码重置、真实用户鉴权与退出；
- 角色/机构/家庭授权、多设备会话、生产 Refresh Token；
- 生产个人信息保护同意、KMS/密钥轮换、备份、真实权限管理后台；
- 医嘱、处方、用药、治疗、复诊 API；AI、OCR、真实医疗预警；
- 正式 PWA 框架、报告/附件上传、修改删除与版本冲突。
  
这些都保留在已有 PRD 和 Issue 中，不以“以后可能需要”为由并入 S2。

## 5. 问题收敛办法

分类只有三种：
- **S2 阻断**：A/B 数据可越权读取/写入、签名可伪造或无校验、身份参数由客户端控制、CI TypeScript 或 API 集成失败、现有业务回归。
- **下轮安全基建**：正式登录提供方、授权与同意、用户管理、KMS/密钥版本、会话吊销、用户数据删除。
- **暂缓**：处方、AI、OCR、家庭成员、报告等不在 S2 的产品功能。

处理顺序固定为“最小重现 → 修复 → 自动化回归”，不在解决编译/测试问题时扩大产品功能。阻断关闭后停止 S2 开发。

## 6. 成果验收与发布阶段门

- 测试须证明 A 与 B 双向访问隔离，且无 token / 错 token / 过期 token 被拒绝。
- 使用 \`npm run test:api\` 运行真实本地 Worker+D1 HTTP 测试；保留 GitHub Actions 成功链接。
- PR 先保持 Draft，基于 \`feature/mvp-s1-core\`，不直接进入 main。
- **正式产品的身份提供方、敏感信息授权、用户数据隔离、云部署区域、KMS 和安全测试全都未完成。禁止处理真实病历。**

S2 的完成仅代表“**本地双虚构账号的资源授权逻辑验证**”，不代表“正式账号/登录已上线”。
