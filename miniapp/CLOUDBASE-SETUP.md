## 下一步：在微信开发者工具中做实际联通测试

1. 拉取 `feature/mvp-s5-cloudbase-dev` 分支，并在微信开发者工具选择“导入项目”，目录为仓库中的 `miniapp/`。
2. 使用有 `wx027f1a9c66e3c01a` 开发权限的微信账号登录，检查「云开发」控制台中是否能找到环境 `health-d2gxjb20h1d33fa91`，确认该环境与当前小程序绑定且地区/计费配额符合预期。
3. 在开发者工具的 `cloudfunctions` 目录找到 `healthDevPing`，选择该云函数并使用「上传并部署」（具体选项以你的开发者工具界面为准）。本函数无第三方依赖。
4. 编译小程序，首页点击「云开发连接测试（默认关闭）」入口。该按钮名称保留原 S5 基线文案；**当前环境已配置，进入页面后「验证云函数连接」应可以点击**。
5. 点击「验证云函数连接」。成功时页面显示：**“云开发测试函数已连接；尚未开启真实登录或健康数据存储。”**
6. 如提示“连接未完成”，依次核对小程序 AppID、环境关联、云函数部署环境、云函数名称及权限；不要通过关闭云环境安全规则或开启真实健康信息存储来排查。
7. 联通完成后，向研发反馈**成功页面提示或脱敏后的报错内容**。当前 GitHub CI 只能模拟调用，无法确认实际云端状态。

## 本次代码变更的安全边界

- `wx.cloud.init` 仅初始化指定环境，不会在启动时自动执行 `wx.cloud.callFunction`。
- `healthDevPing` 无参数输入，不读取用户 OpenID、数据库、文件存储或其他个人信息。
- 页面只接受 `synthetic-read-only`、`canStoreHealthData:false`、`accountAuthenticated:false` 的测试结果。
- 默认 Worker 的 `RELEASE_BLOCKED` 保护、原 A/B 本地虚构身份链路均未改变。
- 当前尚未验证生产用户身份或用户健康数据安全；不能据此上线真实健康记录。
