# Health V0.1 · 可交互原型

**原型状态：需求评审 / 仅供演示。** 该目录不包含可用于真实患者的医疗 AI、诊断或自动分诊服务。

## 如何查看

目录包含：

- \`index.html\`：六个页面的 HTML 结构与人体示意图容器
- \`styles.css\`：响应式视觉样式与打印样式
- \`app.js\`：人体点击、事件联动、用药记录、问询演示、报告汇总逻辑

### 运行方法

从 GitHub 下载本目录中 **这三个文件**，放在同一个本地文件夹，双击 \`index.html\` 即可打开。无 npm、构建工具或后端依赖。也可以使用任意静态文件服务器预览。

**特别说明：** 仓库中的 GitHub 文件预览不是可运行的 Web App。只有通过浏览器打开静态网页入口 \`index.html\` 才能完整体验交互。

## 建议体验流程

1. 打开首页，查看虚构的“腹部不适”健康事件。
2. 点击“记录不适”：在人体图正面选择“上腹部”，也可以切换背面、多选其他区域；点标签填写症状、程度和开始时间。
3. 在“保存到哪个健康事件”中选择现有事件或新建；保存后自动跳至事件时间线。
4. 点击“用药记录”，填写**演示药名**、实际用量、时间并关联事件。
5. 查看“健康事件”，检查症状/用药时间线及事件状态。
6. 在“AI 辅助”页面体验三道补充问询，打开通用紧急提示模板。**不会输出疾病结论。**
7. 在“就医报告”查看报告自动汇总、人体部位示意、用药摘要；可使用浏览器打印功能保存 PDF。

## 核心互动能力

- 正反面人体示意图，支持点击高亮、取消、切换视图与多个区域。
- 左右侧以**人体自身左右**为准，因此人体左侧出现在观看者右方。
- 可跳过人体图；支持“全身/位置不明确”的输入情况。
- 症状可多选；程度 0–10 且可选“无法评分”。
- 事件分组、时间线、状态切换和跨页面动态更新。
- 实际用药信息记录；不计算或推荐剂量。
- 独立的 AI 问询页面与紧急提示**模板**，用于评审 UX，不做医疗判断。
- 就医报告包含症状部位、时间线、用药事实及用户可选的 AI 功能说明；支持复制文本、打印为 PDF。
- 适配桌面和窄屏；窄屏使用底部导航。

## 重要限制

1. **数据仅驻留浏览器当前页面内存**：刷新即重置，不使用 localStorage、IndexedDB、Cookies 或后端数据库。
2. **只使用虚构示例记录**；试用时请勿输入真实病历、身份信息或其他敏感个人数据。
3. 当前人体图为原创的简化 SVG 概念图，主要部位可点击；并非医学级解剖图，也未实现全部二级细分、痛点精确坐标、器官层级或放射方向。
4. AI 问询为固定示例问题，**不根据用户记录进行医学风险判断**；“紧急风险提示”仅是展示样式。
5. 没有账号、同步、导出完整原始数据、审计、删除、加密、API、云端 AI 连接或真正的医学规则库。
6. 用药演示仅收集名称、数量、单位、时间与备注；还需要药物规格、剂型、服用状态和来源等完整字段设计。
7. PDF 导出通过浏览器“打印/保存为 PDF”实现，不代表正式报告生成后端。
8. 该原型没有完成完整的端到端浏览器自动化或真实设备可用性验证；界面演示应进行人工走查。

## 2026-11-17 迭代：二级部位、就医与医嘱、全程报告

本轮在原有六个页面基础上新增 **“就医与医嘱”** 页面；桌面侧栏可直接进入，移动端可从“健康事件”详情进入。

**新增演示流程：**
1. “记录不适” → 点击人体图区域 → 在下方选择整体或细分位置；也可多点选择，再选两个位置记录“延伸方向”。
2. “就医与医嘱” → 选择事件 → “就医记录”填写机构/科室/医生原文。
3. 切换到“医嘱 / 处方” → 可关联一次就诊、记录医嘱原文和来源。它不会自动被当成“已经服药或已治疗”。
4. 切换到“治疗执行” → 记录实际发生的治疗，可关联某条治疗医嘱。
5. “用药记录”新增可选关联的处方选项；**实际服药是单独记录**。
6. “就医报告”可切换**就医前摘要**和**就医与治疗全程档案**；后者按分区显示就诊、医嘱和实际治疗。
7. “AI 辅助”选择不同健康事件时，会基于已有症状/部位选择不同的**预设问题**；仍未调用真实模型或执行临床风险评估。

**已知限制：** 二级部位尚未覆盖全身；“治疗执行”是用户自述输入，未实现医院核验；处方目前仅自由文本，没有多药结构化明细；没有文件上传、原始医疗文书、医学分诊及真实 AI。

医嘱完整业务要求见 \`docs/CARE-AND-ORDERS-V0.1.md\`。
