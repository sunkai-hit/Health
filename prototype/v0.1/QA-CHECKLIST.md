# Health V0.1 原型测试清单

## 检查说明

- 测试对象：\`prototype/v0.1/index.html\` + \`styles.css\` + \`app.js\`
- 使用虚构测试数据；**严禁输入或上传真实健康信息**
- 这是人工走查清单，不代表已执行的测试报告。
- 测试视口建议：375px、390px、768px、1280px。
- 不包含真实医学风险分级，也不能用于验证医疗规则的准确率。

## A. 基础交互

- [ ] 页面在本地直接打开，无外部资源依赖、无控制台报错。
- [ ] 桌面左侧导航及手机底部导航均能切换对应页面。
- [ ] 切页后标题、副标题、当前导航高亮同步。
- [ ] 375px 视口无严重横向滚动、底部按钮可点击。
- [ ] 刷新后恢复虚构示例，不保留输入数据；没有意外网络请求。

## B. 人体图

- [ ] 正面/背面可切换，区域能被点击、高亮和再次取消。
- [ ] 同一视图可选择多个区域，跨正反面选择会保留。
- [ ] 已选标签与 SVG 高亮一致，标签上的“×”删除有效。
- [ ] 人体左右以本人身体为准；选择左侧标签与图形对应。
- [ ] 开启“全身 / 位置不明”会清除具体部位；反向再点取消。
- [ ] 不选择具体位置也可以凭症状文字保存。
- [ ] SVG 区域可通过键盘 Tab 聚焦、Enter/空格切换（需真实浏览器测试）。

## C. 症状与事件

- [ ] 症状标签可多选与取消。
- [ ] 不适程度初始为“未评分”，滑块禁用；用户取消勾选后才记录具体分数。
- [ ] 保存至少需要部位/类型/描述之一，空表单应提示且不创建空事件。
- [ ] 新建事件名称可修改，用户取消命名时不应产生新事件。
- [ ] 新记录可挂接已有事件，保存后出现在对应时间线。
- [ ] 补记发生时间后，时间线按实际发生时间排序。
- [ ] 事件结束/重新开启状态显示一致。
- [ ] 多事件切换后报告和用药关联当前事件一致。

## D. 用药记录

- [ ] 未填药名或用量时不能保存。
- [ ] 有药名/剂量/单位/时间/事件时可添加用药记录。
- [ ] 用药后感受按用户原文显示，不被解释成明确因果。
- [ ] 药名/剂量的 HTML 特殊字符在界面中仅作为文本显示，无脚本执行风险。
- [ ] 用药记录出现在事件时间线、用药汇总和就医报告。

## E. AI 页面和安全提示

- [ ] 页面清楚说明“模拟问询、未启用真实医学分诊”。
- [ ] 3 道示例问询可依次选择答案，包括“不确定”。
- [ ] 结束后显示用户所选答案，不输出疾病概率、诊断或用药建议。
- [ ] 点击“紧急风险提示样式示例”仅展示通用模板，不引用当前事件作个人风险判断。
- [ ] 模板可以关闭，点击遮罩和 Escape 可以退出。

## F. 报告

- [ ] 选中事件后报告显示对应标题、日期和状态。
- [ ] 报告包含用户自述症状、身体部位（含标记示意图）、时间线、实际用药。
- [ ] 缺少症状/用药等信息时正常显示缺省状态，不编造。
- [ ] 默认不附 AI 内容；勾选附加后只显示原型说明。
- [ ] 复制按钮成功时有提示；权限失败时给出替代方式。
- [ ] 浏览器打印输出 A4 布局，无侧栏和表单控件，适合另存 PDF。

## G. 尚未具备的正式产品安全测试

- [ ] 用户身份鉴别、跨用户数据隔离、最小权限。
- [ ] 敏感健康信息的存储保护、传输加密、撤回授权、导出及删除。
- [ ] 第三方 AI 服务数据保留政策与授权验证。
- [ ] 医学审核的危险信号规则、无结果/未知/矛盾信息分支与临床验证集。
- [ ] 负面例子、边界例子、模型升级回归及误报漏报评估。
- [ ] 数据可追溯、修改审计、生成报告快照与临床内容区分。

## H. 新增流程走查（2026-11-17 迭代，待执行）

- [ ] 点击一级人体区域显示“整体”与对应二级选项；选择二级后报告按具体部位展示。
- [ ] 未定义二级部位时仍可记录一级区域。
- [ ] 多个部位支持标记延伸方向；起终点相同或缺失其一时应提示，不应保存错误关系。
- [ ] 进入“就医与医嘱”，分别添加就诊、医生建议和实际治疗三类条目。
- [ ] 未关联就诊也可以记录医嘱；同一就诊允许多条医嘱。
- [ ] 医嘱状态为“未执行/不确定”时不会凭空出现服药/治疗执行事实。
- [ ] 实际治疗可关联原有治疗医嘱；同一医嘱可关联多次独立治疗。
- [ ] 实际用药可选关联处方；未关联处方时保存独立用药事实。
- [ ] 事件时间线分别展示就诊、医嘱、治疗与用药，时间排序正确。
- [ ] 报告“就医前摘要”主要显示症状和实际用药，不将医嘱当成实际用药。
- [ ] 报告“就医与治疗全程档案”有独立就诊、医嘱/处方、实际治疗、实际用药分区。
- [ ] 报告和时间线明确区分“用户转录的医嘱”与真正经过医疗机构核验的记录。
- [ ] 切换 AI 演示事件，预设问询可根据腹部、头部、胸部等部位变化；不产生医学诊断或个人风险等级。
- [ ] 移动端从事件详情能进入“就医与医嘱”，报告双视图操作完整。
- [ ] 对各输入字段使用特殊字符进行显示转义测试，避免 XSS。
- [ ] 清空表单、切换事件、多次保存、刷新页面后没有错误的数据关联或隐式持久化。

## I. 处方、医嘱版本与复诊管理走查（待人工执行）

- [ ] 处方类型显示“多药明细”，其他类型不展示；增加、删除多条药品时输入不丢失。
- [ ] 存在填写了规格/剂量但没有名称的行，应提示补正或移除。
- [ ] 剂量/频次/疗程不清楚时可以留空，不自动猜测。
- [ ] 选择图片/PDF 时只在本地预览；无 OCR；不生成已核验医嘱。
- [ ] 8MB 以上或不支持类型文件能提示并拒绝。
- [ ] 新版处方选择旧版医嘱时，仅允许同类型；旧医嘱原始文本和明细保留。
- [ ] 用户在“实际用药”中关联某张处方后，能够继续选择对应药品明细。
- [ ] 处方含药品甲和乙，仅甲有实际用药记录时，对照只统计甲有记录；乙展示“未关联”而不是“没服”。
- [ ] 不确定药品时只关联整方，不能自动计入所有药品的服用次数。
- [ ] 复诊计划包含日期和原文，未关联实际就诊时不能显示“已复诊”。
- [ ] 新建实际就诊并关联复诊计划后，报告显示两条不同的时间记录。
- [ ] 全程报告包含医嘱明细、历史版本、复诊计划、实际执行对照。
- [ ] 所有录入文本以安全文本方式显示，不出现 HTML 注入。
- [ ] 刷新页面后全部新增用药/医嘱/文件预览重置为虚构数据。
- [ ] 375px 和 1280px 屏幕均可操作，长药名、长处方、报告分页不溢出。

目前只进行了 JavaScript 静态解析和页面控件一致性检查，尚未完成上述真实浏览器端到端测试。
